# 🔑 Git identities

Two identities coexist inside the devbox, each with its own SSH key for authentication **and** commit
signing. The directory a repo lives in selects the identity - there is no manual switching.

| Scope                   | Identity         | Key                  | Remote host      |
|-------------------------|------------------|----------------------|------------------|
| everywhere              | `GIT_PERSONAL_*` | `~/.ssh/id_personal` | `github.com`     |
| `~/projects/work/**` | `GIT_WORK_*`  | `~/.ssh/id_work`  | `github-work` |

The override is an `includeIf gitdir:~/projects/work/` block in `~/.gitconfig` pulling in
`~/.config/work/.gitconfig`. Both keys are generated by `bootstrap`, passphrase-less, and never leave the
bind mount: per-host, individually revocable on GitHub, and usable by unattended agents without a prompt.

## Cloning

```bash
git clone git@github.com:rozsival/<repo> ~/projects/rozsival/<repo>  # personal
git clone github-work:<org>/<repo> ~/projects/work/<repo>     # work
```

`github-work` is a `Host` alias in the container's `~/.ssh/config` pointing at `github.com` with
`IdentityFile ~/.ssh/id_work` and `IdentitiesOnly yes`.

**The work alias cannot be skipped at clone time.** The `url."github-work:".insteadOf=git@github.com:`
rewrite lives inside the `includeIf` file, and Git only loads that file once the repo directory exists. A
`git@github.com:` URL would therefore go out over the personal key. Repos already inside
`~/projects/work/` have their remotes rewritten automatically from then on.

`gh repo clone` works for personal repos (`gh config` sets `git_protocol ssh`); for work, clone by alias so
the remote URL is right from the start.

Confirm which identity a repo picked up:

```bash
cd ~/projects/work/<repo>
git config user.email        # you@work.example
git config user.signingkey   # /home/dev/.ssh/id_work.pub
git remote -v
```

## Signing

`bootstrap` sets `gpg.format=ssh`, `commit.gpgsign=true`, `tag.gpgsign=true` and
`gpg.ssh.allowedSignersFile=/home/dev/.ssh/allowed_signers`, so every commit is signed by the identity's key
and verifies locally as well as on GitHub. The macOS-only `gpg.ssh.program = op-ssh-sign` is deliberately
absent - the default `ssh-keygen` signer is used instead.

```bash
git log --show-signature -1                      # Good "git" signature with ED25519 key
gh api repos/<owner>/<repo>/commits/<sha> --jq .commit.verification    # verified: true
```

## GitHub registration

Each key must be added to GitHub **twice** - once as an Authentication key, once as a Signing key. They are
separate key types; one registration does not imply the other.

```bash
ssh workstation 'cd ~/devbox && ./bin/devbox keys'    # prints both public keys + host-key fingerprint
gh ssh-key add ~/.ssh/id_personal.pub --type authentication --title devbox-personal
gh ssh-key add ~/.ssh/id_personal.pub --type signing     --title devbox-personal
```

`gh ssh-key add --type signing` needs the `admin:ssh_signing_key` scope:
`gh auth refresh -h github.com -s admin:ssh_signing_key`. Pasting into the GitHub web UI works equally well.

Verify auth per identity:

```bash
ssh -T git@github.com          # Hi <user>!  - personal key
ssh -T github-work          # Hi <user>!  - work key
```

## ❓ FAQ

**Can I put a personal repo outside `~/projects/rozsival/`?**
Yes. The personal identity is the global default; only `~/projects/work/**` is overridden. The
`~/projects/rozsival/` convention is organisational, not functional.

**I cloned an work repo with `git@github.com:` by mistake. How do I fix it?**
Nothing is broken - the `insteadOf` rewrite applies now that the directory exists. Confirm with
`GIT_TRACE=1 git fetch 2>&1 | grep ssh` that the work key is used, or set the URL explicitly:
`git remote set-url origin github-work:<org>/<repo>`.

**Why passphrase-less keys?**
Unattended agents must push without a prompt, and the keys are already inside a Tailnet-only sandbox on a
bind mount only the host user can read. The mitigation is scope, not a passphrase: each key is per-host and
revocable on its own.

**Why no agent forwarding?**
`AllowAgentForwarding no`. Signing and GitHub auth use keys that live inside the devbox, so forwarding would
only widen the blast radius of a compromised sandbox.

**A push says `Permission denied (publickey)`.**
The key exists but is not registered as an *Authentication* key, or the wrong identity is in play. Check
`ssh -T git@github.com` and `git config user.email` in that repo.

**Commits show as unverified on GitHub.**
The key is missing as a *Signing* key, or the commit email is not attached to the account. Local
`git log --show-signature` passing while GitHub says unverified always means the former.

**How do I run two `gh` accounts?**
`gh auth login` once per account, then `gh auth switch --user <login>`. Both tokens persist in
`~/.config/gh` on the bind mount. See [Secrets](secrets.md).
